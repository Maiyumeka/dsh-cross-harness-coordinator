# 0.2.7：Codex 大图片事件与逐任务日志

对应 [Codex image delivery 工单](缺陷工单-0.2.6-codex-image-delivery.md)，以及用户提出的增加日志要求。

## 复现和判断

0.2.6 的 JSONL RPC 和 Codex WebSocket 都只接受1MiB。工单中指定的PNG实际大小为1,993,793字节，1672×941；base64长度至少2,658,392字节。本机Codex CLI 0.160.0生成的Schema明确包含 imageGeneration 的 result 字符串、savedPath、status。未读取rollout聊天记录或凭据，也未重新生成真实图片。

用同样大小的合法图片完成事件在改动前复现：ok=false、错误“Codex在完成事件前退出”、lastNotification=item/started、approvals=[]、复制请求未到达、目标文件不存在。传输层在解析大事件前停止进程，随后等待完成事件的代码只观察到退出，丢掉“消息超限”这一首因。该客户端缺陷确定可复现；它对现场的解释仍须新版日志验收，不能把未取证的os-probe失败也归为同一原因。

工单Q1/Q3有两点需区分：审计push发生在scope判断和codexApproval之前，验证异常会留下audit.reason；复制命令仅检查cwd，不解析源路径，不能因源图位于CODEX_HOME就推断路径校验必然失败。源图在另一盘的普通复制命令已用独立夹具验证。手工accept能完成，不说明旧客户端没有在更早的传输层停止。

## 修正

Codex stdio和WebSocket上限统一为16MiB，仍限制单消息与未完成缓冲；MCP保持原协议限制。有效图片事件后继续接收命令与审批，图片块不会放进items缓存或结果审计。只记生成项目ID、状态、源图路径和编码长度，支持标准imageGeneration以及工单所述extension包装。

RPC保留第一个错误并向“等待turn完成”阶段传播，不再被停止进程或清理覆盖。native.transport保存错误代码、类别、字节/上限和统计，native.termination区分调用方取消与本地截止期限。正常清理不冒充传输失败；解码异常不把原始输入片段写到日志。

本轮没有自动从默认目录拿图片放行失败任务。生成事件完成不等于收到turn/completed，不等于声明产物已交付，也不等于视觉验收通过。单次操作审批保持0.2.6流程，未修改沙箱/审批配置，未添加所谓“-c sandbox_policy”或危险跳过参数。DSH权限与Codex自身配置不能仅凭同名说法假定一致。

## 新日志

按会话、任务和runId在dataDir/run-logs写独立JSONL，标识用于文件名时先哈希。事件包括rpc_message、rpc_server_request、codex_request_enter、approval_forwarded/rejected、approval_engine_enter/rejected/decided、codex_image_completed、rpc_failure/exit、codex_deadline/failed和run_started/finished。

native请求进入时先记方法/item/turn身份，engine每个准入阶段的拒绝记stage与原始异常原因；因此可以区分“请求没到/没解码”“native收到后拒绝”“引擎拒绝”“原会话未批准”。stdout文字与有界stderr仍在失败result内，诊断日志不再重复存储正文、提示词、原图base64、密钥或聊天记录，只记允许字段；常见凭据形态隐藏。每份日志最多1MiB，超过时记录截断，写入失败在摘要中报告。

task.diagnosticLog和result.diagnosticLog给出路径、字节数、条数及完整性状态；重新运行生成新文件，历史结果保留原日志指针。原会话可以在设置页点“查看运行日志”，或由Agent调用coordinator_control action=log携带任务id。读取路径由插件计算，外会话、任意路径和越界链接不接受。

## 验证范围

codex-image-delivery.mjs使用有效的1像素PNG加大ancillary块作为无模型测试数据：标准/分片/extension图片帧超过2.6MB，三次单次审批后从工作区外的测试缓存复制到声明scene1.png，源/目标SHA-256一致。另测16MiB以上拒绝、JSON损坏首因、图片生成后退出仍失败、可控时钟超时、WebSocket大帧与日志转接、原会话读取、日志上限/字段白名单及交付后仍须审查。

界面回归的12组检查全部通过，包括查看运行日志、原审批/结束任务/历史产物与窄屏。核心新增此套件，共14项；最终源码连续运行两轮，28/28通过，真实模型调用为0。发布包40个文件逐一核对源码哈希。最终日志与打包哈希见dist/验收记录-0.2.7.json。协议依据采用本机Schema，并对照[官方App Server文档](https://learn.chatgpt.com/docs/app-server)。

没有触碰正式任务、Codex配置、聊天记录或现有生成图；没有重新派发art-scene1/os-probe或调用真实模型。新版源码与安装包不等于正式DSH已经安装并完成图片任务验收。
