# 0.2.4：MCP 慢启动、共同预算与可追踪回执

对应 [0.2.3 auto 工单](缺陷工单-0.2.3-mcp-auto.md)。本轮修复了发现时限早于实际网关响应、握手阶段重新计算完整预算，以及失败回执缺少实际模式和停止原因的问题。历史 DSH 失败仍需新版回执验收，不能只凭一条 modern 记录断定具体原因。

## 复测得到的事实

2026-10-06，用正式登记的同一 OpenSquilla 可执行文件、参数和工作区做独立无任务协议探测。临时选择模式只存在于测试请求里，没有改正式协调器状态，没有调用 messages_send 或其他 tools/call。

| 客户端 | 临时模式 | 结果 | 时间 |
|---|---|---|---|
| 改动前 0.2.3 | auto | 发现 1.5 秒超时，换新连接；legacy 2025-11-25，6 个工具 | 约 4.92 秒 |
| 本轮改动 | auto | discover 在约 2.99 秒响应；现代 2026-07-28，6 个工具 | 约 3.24 秒 |
| 本轮改动 | legacy | initialize 2025-11-25，6 个工具 | 约 3.17 秒 |

因此 0.2.3 的降级本身可以成功，但 1.5 秒确实早于此入口的启动响应；本轮延长有界发现时间后，带正确元数据的现代握手也成功。不能再凭裸请求的 Method not found 把这个入口判为不支持现代协议，也不能推断历史测试时服务端一定处于相同状态。

探测使用测试启动器，不是正式 DSH 宿主沙箱。它证明同一登记入口与客户端代码兼容；DSH 内实际安装后的 auto 验收另行进行。复测时正式端点仍为 0.2.3 下的 legacy ready，本轮没有自动更新安装或改接入定义。

工单里的其他推断也须区分：默认 era 是 legacy；0.2.3 已处理普通 discover 错误和超时，并非只识别 -32022。正式连接检查硬期限是 15 秒，不是从约 8 秒观测反推的预算。旧回执没有 requestedEra、signal 状态、取消来源或清理耗时，不能据此确认命中了哪一个退出条件。

## 本次调整

连接检查把绝对 deadline 从协调器传到版本预检和握手层。预检、宿主启动、discover、旧进程清理和新连接共用剩余预算，重连不再获得一段新的完整时限。发现请求等待最多 4 秒，并限制为剩余预算的三分之一，为旧握手留下时间。

普通错误或请求级超时仍会换新连接降级。调用方取消、15 秒检查期限到达、总预算耗尽、损坏传输和已识别的现代版本拒绝仍会停止；不会撤销 signal 或越过总时限来反复启动进程。modern 强制模式保持严格，任务 tools/call 不重放。受管进程停止可能使返回晚于期限，回执记录清理耗时且超期不会假报连接就绪。

成功和失败回执均保留 negotiationAttempts 与 diagnostics：实际 requestedEra、请求/总预算、启动和清理耗时、signalAborted、abortSource、failedPhase，以及 fallbackDecision 的 reason/blockedBy。即使取消发生在最终清理，也不会丢掉之前的尝试记录。没有 legacy 条目还可能表示进入了重连但清理或启动未完成；须同时看 stage 和 blockedBy。

设置中的“连接检查记录”显示本次模式、尝试结果和停止原因；旧回执的模式显示“旧回执未记录”，不拿当前配置冒充历史请求。详细工具回执仍可供 Agent 排查。邀请耗尽后仍要求原登记会话 connect 或新邀请；不增加同一邀请的重试次数。

协议依据：[MCP stdio 向后兼容规则](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio)。

## 验证与正式验收

核心套件新增 mcp-budget.mjs，覆盖请求超时可降级、共享期限、版本预检耗时、发现期间的调用方取消/检查期限、重连和最终清理超期、损坏传输，以及已取消请求不启动进程。mcp-negotiation.mjs 增加 2.1 秒慢启动夹具和实际模式/禁止降级原因断言。defects-ui.mjs 验证界面显示实际模式、双路径记录及强制 modern 的停止原因，同时保留单任务结束、历史产物和窄屏验证。测试均不派发模型任务。

本轮核心测试 **12/12 通过**（58.7 秒），独立 Edge 界面测试通过；发布包包含 34 个文件，包内源码与清单哈希检查通过。本机安装前检查识别桌面运行时 0.2.0-rc.2，当前已安装协调器 0.2.3，待处理任务/活动连接均为空。这些结果不等同于已经在正式 DSH 中安装并运行 0.2.4。

真实入口复测脚本 test/live-mcp-probe.mjs 只在显式提供本机状态路径和端点 ID 时运行，不在默认测试里，不打包，不发布本机状态。它只发送 discover/initialize/initialized/tools/list。

安装 0.2.4 后，原登记会话按 AGENT_INSTALL.md 完成运行版本核对；如需正式 auto 验收，使用 coordinator_control action=connect 修正该端点，保留完整 mcp.transport/tool/arguments 等字段，只改 era。不要手改正式 state.json，也不要绕过任务引用和指纹确认。看新版 diagnostics.requestedEra 确认本次实际模式，再判断握手与降级。已有 legacy ready 无需为了升级自动重接或重放任务。

worktree 的 `.local-install.json` 不随 Git 复制；已在 AGENT_INSTALL.md 补充本机配置和环境变量说明，发布清单缺 cli/asar 时重新生成，不绕过检查。
