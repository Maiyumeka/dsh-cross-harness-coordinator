# 0.2.3：MCP 自动降级和重试指引

对应 [MCP 工单](缺陷工单-0.2.2-mcp.md)。工单中的客户端错误和直接探测结果不同，服务端连接状态被探测影响仍是推测。这里修复可复现的客户端连接复用问题，不把该推测当成已经证明的服务端根因。

## 接入配置

`mcp.era` 只接受 legacy、auto、modern。2025-06-18 是 initialize 返回的 protocolVersion；它属于支持的旧握手版本，不能填到 era。已实测支持 initialize 的网关应优先选择 era=legacy。客户端依然验证返回版本、tools/list 与任务参数映射，不会把只有初始化响应算成完整接入。

当前 OpenSquilla 登记端点为 h_0c3e90b77b86，配置是 era=modern，错误阶段为 server/discover。修正应由登记它的 DSH 会话执行 connect，保留已有完整 mcp 定义，仅将 era 改为 legacy。无需安装新版即可使用这一已有入口；本版进一步改善 auto 和诊断。

## 自动协商

0.2.2 在 discover 返回普通错误或超时时已经会降级，不是仅处理 -32022。缺少的是重新建立连接：0.2.3 在 auto 降级前关闭旧进程，再由同一宿主沙箱启动新进程发送 initialize。旧进程结束回调不再干扰新进程待处理的请求，清理失败、宿主拒绝、取消和总超时不会被当成可用连接。

modern 模式保持严格；已识别的现代协议版本拒绝不能绕过成旧握手。negotiationAttempts 同时保存现代发现和旧握手的结果，错误分类有界，不保存不必要的大段服务端数据。这里只允许无任务协商重试，不重放 tools/call。

协议依据：[MCP stdio 向后兼容规则](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio)。

## 邀请和审计

retryAllowed=false 后的提示明确要求登记会话 connect 或新邀请，不再让 Agent 经同一邀请继续提交。原两次上限保留，connect 仍受端点归属、任务引用、调用定义和指纹保护。

工单还指出执行端移除没有事件：本版补上 endpoint_removed，记录会话、名称和编号。此变更不能解释过去两条执行端的消失，也没有自动恢复它们。

## 验证

mcp-negotiation.mjs 用独立夹具模拟 discover 拒绝/静默后连接状态改变，验证新进程成功协商 2025-06-18；现代拒绝、强制 modern、双路径失败、宿主拒绝和取消仍失败。邀请耗尽后，拥有者通过 connect 改为 legacy 能完成握手与工具映射，且没有 tools/call。正式 OpenSquilla 连接仍须在登记会话验证。
