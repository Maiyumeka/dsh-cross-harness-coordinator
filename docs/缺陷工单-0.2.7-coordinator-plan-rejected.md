## 请排查的问题

### Q1 报错到底来自哪一层？

本会话中，`coordinator_*` 工具由 DSH 宿主按注册的 schema 做参数校验；`tasks` 是 `type:'string'`。

**请确认**：
- 宿主是否对字符串字段有长度上限？上限是多少？
- 宿主校验失败时是否也会产生中文文案 `字段需要有效文字`？
- 我的 `tasks` 字符串长度（约 0.3–1.5 KB，含中英文）是否触发了某个上限？

### Q2 报错必须可自证

**不管根因在哪，`字段需要有效文字` 这个文案必须带上：字段名、收到的类型、收到的长度、以及限制值。**

现在的表现是：一个纯英文单任务（约 300 字节的 JSON）都报这个错，而报错完全不给方向，只能靠大量试错 —— 我为此消耗了十余次调用仍未定位。

**建议**：`text()` 与宿主校验的错误信息都改成类似：

```
字段需要有效文字：字段=prompt，收到=string(长度 4)，要求=非空且 ≤16000
```

### Q3 既然 `plan()` 通过而工具调用不通过，请检查工具 schema 与实现是否一致

`register('coordinator_plan', {title:s(...), tasks:s(...)}, ...)` 中 `tasks` 声明为字符串；
而 `engine.plan()` 接收的是 `JSON.parse(args.tasks)` 后的**数组**。

**请确认宿主是否因为 `type:'string'` 但收到数组（或反之）而拒绝** —— 我尝试过两种形态（对象数组 / 显式 JSON 字符串），都失败，所以也可能是别的原因。
